# Audit #99 remediation and verification map

This change implements the owner-requested audit remediation plus runtime-only worker credentials. It does not authorize a real DP upgrade, production deployment or a release. The live Issue/PR binds test receipts to the exact candidate commit.

## Operator credential contract

The Mirror Manager does not collect, persist, require or hash worker passwords. Configuration contains preparation mode, mirror IP and DL/DA worker IP lists. Within Configuration, item 5 tests R2 connectivity and item 6 saves settings; main-menu item 7 is unchanged.

Cluster commands generated by Menu 7 include `--prompt-worker-password`. The operator enters the secret on the designated DP master with terminal echo disabled. The lifecycle creates a mode-0600 credential file on the DP, passes only the file path to its worker, and removes its own credential at termination. A reattach to an existing worker does not prompt or overwrite its credential. AIO and workerless-master commands do not prompt. Legacy explicit DP CLI password/file options remain compatibility inputs, not a second Mirror configuration workflow.

Legacy Mirror `WORKER_SSH_PASSWORD` is ignored on load and removed when the operator saves configuration or bootstrap rewrites it. Existing external backups are not silently destroyed. The retired value does not contribute to workflow/command identity. Password rotation therefore requires neither a Mirror config change nor another artifact download.

## Compatibility and safety

Existing unbound operator PASS receipts do not silently qualify a new run. Operators must confirm the current completed run again. This is intentionally fail-closed. A version mismatch never automatically starts a new upgrade. Artifact recovery may still run before disk-space checks, but never before bringup-consumer exclusion.

The private DP credential's lifetime is independent of Mirror configuration. Truly external password-file inputs are not deleted. An older worker cannot remove a new file that has replaced its credential inode.

## Verification boundary

Tests use temporary roots, dummy credentials and harmless vendor/readiness substitutes where required. The runtime prompt test uses a real pseudo-terminal to verify echo masking, no secret on worker argv/log output, file mode and cleanup. These are deterministic regression results, not proof of an actual AWS OS/DP upgrade. Full physical/reboot/DP validation remains a separately authorized disposable-lab exercise with the existing snapshot safeguards.
